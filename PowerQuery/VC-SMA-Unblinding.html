VC SMA confidential name unblinding

A confidential investment is shown by its real name when another investment with the same name has no blinding requirement. This page explains the Power Query logic and lets you try it.

The rule Try it The code Limits Maintaining it

The rule

Each investment row carries a Client Blind in QR flag. A value of "1" means the name must be hidden. Anything else, including blank, means it can be shown.

If one or more rows that share a Fund Name Final are not flagged, that name is already public. Every flagged row with the same name is then unblinded too. Flagged rows with no unflagged match stay as "Confidential" plus the Investment ID.

  1. Find the public names. Collect every Fund Name Final that has at least one unflagged row. Names are trimmed and compared without regard to case. Blank names are ignored.
  2. Flip the flag. For each flagged row whose name is in that list, set Client Blind in QR to "0".
  3. Build the display name. Anonymized Fund Name Final shows "Confidential ID" if the final flag is "1", otherwise Fund Name Final. This is the column the visuals use.

This replaces the old manual replace steps. There is no hardcoded list to maintain.

The code

This block sits after your last column-shaping step (#"Renamed Columns" here). Everything before it is unchanged.

// ===== ALIAS UNBLINDING LOGIC (VC SMA) =====
// Blinded only if the flag is "1"; blank or anything else counts as unblinded
is_blinded = (v) as logical => Text.Trim(Text.From(v ?? "")) = "1",

// Names with at least one investment that has no blinding requirement (ignores blank names)
unblinded_aliases = List.Buffer(
    List.Distinct(
        List.Transform(
            Table.SelectRows(#"Renamed Columns",
                each not is_blinded([Client Blind in QR]) and Text.Trim([Fund Name Final] ?? "") <> ""
            )[Fund Name Final],
            each Text.Lower(Text.Trim(_))
        )
    )
),

// Compute the final flag per row as a new column (blinded rows whose name is public become "0")
alias_flag = Table.AddColumn(
    #"Renamed Columns",
    "Client Blind in QR Final",
    each if is_blinded([Client Blind in QR])
              and List.Contains(unblinded_aliases, Text.Lower(Text.Trim([Fund Name Final] ?? "")))
         then "0"
         else Text.From([Client Blind in QR] ?? ""),
    type text
),

// Swap the new flag in for the original
alias_final = Table.RenameColumns(
    Table.RemoveColumns(alias_flag, {"Client Blind in QR"}),
    {{"Client Blind in QR Final", "Client Blind in QR"}}
),
// ===== END ALIAS LOGIC =====

// Display name built from the final flag
#"Added Conditional Column" = Table.AddColumn(alias_final, "Anonymized Fund Name Final", each
    if is_blinded([Client Blind in QR])
    then Text.Combine({"Confidential", Text.From([Investment ID], "en-US")}, " ")
    else [Fund Name Final], type text)
in
    #"Added Conditional Column"

What each piece does

is_blinded
One definition of "blinded", used three times. It handles the flag arriving as 1 or "1", with spaces or nulls.
unblinded_aliases
The list of public names. List.Buffer stops Power Query from rebuilding the list for every row. The blank-name check keeps empty names from unblinding every row that also has an empty name.
alias_flag and alias_final
Work out the final flag for each row in a new column, then replace the original flag with it. Table.ReplaceValue is not used because it cannot look at other columns in the same row. The result is always text, so 0 and "0" never mix. The flag column moves to the end of the table.
Last step
Builds Anonymized Fund Name Final from the updated flag, so it has to run after the flag changes.

Limits

Names must match
Matching ignores case and surrounding spaces, but a different spelling or an extra word is a different name and will not unblind.
No match, no unblinding
A flagged investment with a name nobody else shares stays "Confidential ID". That is intended.
Only the data pulled
The logic sees the rows returned for that report. If the unflagged match sits in a different pull, the flagged row stays blinded.
Step order matters
The flag change has to come before Anonymized Fund Name Final is built, and after Fund Name Final exists.

Maintaining it

A name still shows as Confidential
Check whether any row with that name has a flag other than "1". If every row is flagged, nothing unblinds it automatically. Fix the flag at the source, or add an override step for that investment.
A name is unblinded that should not be
Look for an unflagged row with the same name. That row is what triggers the unblinding.
The "i" icons next to steps
These are the // comments appearing as step descriptions. They are not warnings.
Changing which column groups the names
Replace Fund Name Final in unblinded_aliases and alias_flag with the new column.
